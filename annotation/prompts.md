# LLM 标注提示词模板（Prompts for LLM Annotation）

标注流程使用三类结构化提示词，分别用于**候选标签归纳**、**一级标签分类**与**低置信样本的 DeepSeek 复核**。
运行时填充 `{text}`、`{label_list}` 与模型输出项；温度与 JSON 输出约束在接口层强制（见 `annotate.py` / `distill.py`）。

---

## Prompt 1 — 候选标签归纳（Candidate-label induction）

```
你是一名医院客服业务分析助手。请阅读以下患者咨询文本，在不预设任何类别清单的前提下，归纳该文本所涉及的：
(1) 服务对象（患者/家属/职工等）；
(2) 办理事项（挂号、缴费、检查、取药、投诉等）；
(3) 管理场景（门诊、住院、医保、后勤等）。
请以简短标签形式输出，每条标签为"业务对象-办理事项"或"管理场景-事项"结构，可输出多个标签。
仅输出标签，格式为 JSON 数组，例如：["门诊服务-预约挂号","医保服务-报销咨询"]。
患者咨询文本：
{text}
```

---

## Prompt 2 — 一级标签分类（First-level classification）

```
你是一名医院患者客服分类专家。请将以下患者咨询文本归类到且仅到一个一级业务标签。
候选标签列表：{label_list}（共20类）。
判定规则：以患者"下一步需要医院哪个部门或流程响应"为优先；高交叉类别按主诉求优先；无法判定的归入"其他"。
仅输出一个标签，格式：{"label": "<标签名>"}。
患者咨询文本：
{text}
```

20 个一级标签（与 `classification/label_mapping.json` 一致）：

```
门诊服务, 住院服务, 急诊服务, 医保服务, 药品服务, 检验检查服务, 手术麻醉服务,
康复护理服务, 健康管理服务, 远程医疗服务, 公共卫生服务, 医疗费用管理, 病案档案管理,
行政后勤管理, 人力资源管理, 信息化管理, 质量安全管理, 便民服务, 投诉建议管理, 其他
```

## Prompt 3 — 低置信复核（DeepSeek low-confidence reassessment）

```
你是一名资深医院客服审核专家。以下患者咨询文本，三个标注模型给出分歧结果：
模型A：{label_a}，模型B：{label_b}，模型C：{label_c}。
请判断：是否支持其中某一个模型的结果？若支持，输出该标签；
若文本暴露了现有20类标签未覆盖的新业务语义，输出新标签；
若信息不足或无法判定，输出"待定"。
仅输出 JSON：{"decision": "support"|"new"|"pending", "label": "<标签名或空>"}。
患者咨询文本：
{text}
```

## 标签体系构建（四步迭代，见论文 §2.2）

1. **候选标签归纳**（Prompt 1，高召回）→ 约 1,059 个原始候选标签。
2. **语义合并**（同义/近义/上下位合并 + 异常剔除）→ 102 个中间标签，遵循三项原则：业务对象优先、客服可执行性、主诉求优先。
3. **一级标签定稿**：六项决策标准——业务路由一致 / 语义边界清晰 / 样本可训练 / 高风险保留 / 混淆可控 / 外部可解释。
4. **人工审阅与边界修订**：业务经验人员审阅 + 边界案例库 + 与标注/复核迭代。

最终形成 20 个互斥一级业务标签（`classification/label_mapping.json`）。
